# 维护 dotfiles

仅在本项目内使用。将下列相对链接按本 skill 所在目录解析，将操作命令在仓库根目录执行。

## 确认任务

1. 读取[项目约定](../../../AGENTS.md)和 [README](../../../README.md)，查看 Git 工作区，区分用户已有改动与本次任务。
2. 明确要改的是共用 source `common/`、系统 source、根目录软件清单、项目 `.agents/`，还是供用户全局部署的 `common/dot_agents/`。不要混用项目与用户级路径。
3. 按任务读取[使用教程](../../../docs/usage.md)、[macOS 软件说明](../../../docs/macos.md)或 [Linux 软件说明](../../../docs/linux.md)，不要全量读取私人家目录。

## 修改配置或 agent 文件

- 共用规则与 skills 只放 `common/`；其他配置选对应系统的 source。从本机收录文件时先检查内容、符号链接和目录范围，只添加明确需要的文件或已审查目录。
- 判断哪一份是用户希望保存的版本。`add` 是本机到 source，`apply` 是 source 到本机；不要用 add 覆盖刚编辑的 source。
- 保持 chezmoi 的命名与属性语义，检查 `dot_`、符号链接、模板以及忽略规则，尤其是嵌套的 `.agents/.skill-lock.json`。
- 对 agent 文件保留所需引用、资源与许可证，排除生成缓存；不在项目维护过程中执行 skill 的业务脚本。
- 删除淘汰项后搜索并清理当前引用，不另存一份。更新软件说明和受影响的测试，不记录整理经过。

## 更新软件登记

- 按[教程的软件清单步骤](../../../docs/usage.md#5-更新软件清单)用 mpm 导出到 `tmp/`，不要重新实现导出脚本。
- 只有本次导出成功后才检查 TOML、选定管理器和条目变化；注意当前 Node 环境会影响 npm 全局包范围。
- 核对差异后更新根目录相应 TOML。Mac 完整导出时包含 mpm 的 `[uvx]`，并核对它未因当前 uv 不满足版本要求而意外缺失；项目专用的 `[manual]` 不由 mpm 导出，先按实际应用信息复核，再按教程补回。`[manual]` 不冒充 Cask，Zoom 已在 `[cask]` 中。没有目标系统的实际登记，不填写猜测版本；不执行恢复或安装。

## 验证与交付

- 配置或目录结构变化时运行根目录 `AGENTS.md` 中的隔离测试；需要新增行为检查时沿用 `tests/` 的方式，不写入实际家目录。
- 项目 agent 配置变化时，检查它没有进入 common 或系统 source，也没有进入全局目录；验证 Markdown 引用及 skill 元数据。
- 检查 Git diff 和新增文件，确认无秘密、缓存、遗漏引用或无关改动；不自动 commit/push。
- 简短报告结果、实际验证及剩余风险。对仅有语法或渲染验证的配置，不声称已在目标应用或系统上实测。
